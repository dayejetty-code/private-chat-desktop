Private Chat 0.10.11 · Windows 维护候选版

本版在已有 scrypt/AES 口令保护之外加入 Windows 当前用户绑定，并更新运行组件；继续移除备份创建、恢复和删除入口。保留文字与 TXT 附件、强制 Tor、Windows 网络隔离、未读提示、连接修复和本机身份销毁。候选版测试不会自动替换桌面的 0.10.10。

新建资料：口令至少 16 个字符，建议使用多个随机词。随机数据密钥由 scrypt 派生的密钥与 AES-256-GCM 保护，外层再通过 Windows DPAPI 绑定当前用户。解密同时需要聊天口令和 Windows 用户的保护密钥。口令不会保存或上传。重装 Windows、删除用户或丢失系统密钥后，即使记得聊天口令，资料也可能永久无法恢复。这不是硬件 TPM 绑定，不能防止已控制当前用户或系统的恶意软件。
已有资料：原口令仍可解锁；旧资料不会自动升级。打开“数据销毁”，输入当前口令，点击“升级本地加密保护”。升级全程离线，保留身份、联系人和聊天；成功后清理本次迁移产生的旧副本。提交前升级失败保留回退资料；若提示迁移未完成，请保留整个资料目录并重新启动应用。升级后需要 0.10.11 或更新版本，旧版无法打开；重新运行 0.10.10 不能撤销这次密钥升级。
取消备份不会删除或废止以前的备份，也不能阻止系统快照或第三方同步软件复制目录。本版没有任何备份操作入口；设备损坏、口令或密钥丢失可能导致资料永久丢失。以前另存的备份文件需在 Windows 文件管理器中自行处理。
销毁身份仍保留另存备份和导出 TXT；旧备份及对应口令仍可能通过兼容的旧版软件恢复旧身份。SSD 残留、系统快照、分页/休眠和已复制密钥不在清除保证范围内。

1. 本次为本地开发测试版，打开新版文件夹中的 PrivateChat.exe 或对应桌面快捷方式。请保留完整 runtime 文件夹；无需另装 .NET。本次没有更新公开下载的安装包。
2. 首次使用时设置至少 16 个字符的资料库口令，建议较长随机词组。口令不保存、不上传，遗忘后无法找回。
3. 等待“Tor 通道已建立”。可选择 obfs4 或 Snowflake 网桥。中继入口默认优先 .onion；邀请超时时可改为“公共域名（经 Tor）”后重新连接，仍强制经过 Tor。
4. 用“添加联系人”生成一次性邀请，或粘贴对方完整邀请。
5. 通过另一个可信渠道核对双方安全码；双方显示相同是正常的。输入对方提供的代码完成核验后才能发送。
6. 文字：点击发送或按 Ctrl+Enter。以会话中的送达状态为准。
7. 文本附件：点击“发送 TXT”，仅选择 .txt 纯文本，确认收件人后发送。原文件与转换后的文本均须不超过 25 MB；不支持 Word、PDF、图片和压缩包。支持 UTF-8（可带 BOM）及带 BOM 的 UTF-16，统一发送为不带 BOM 的 UTF-8。其他编码请用记事本另存为 UTF-8。
8. 收到 TXT 附件后，点击“接收文件”。下载完成后点击“另存为…”，保存为新的 .txt 文件。另存为前检查内容并统一为 UTF-8；校验失败则不生成普通文件。不会覆盖已有文件，不会自动打开。
   “另存为”导出普通文件，不再受聊天资料库口令保护，也不会随锁定清除。突然断电或强制终止导出可能留下不完整文件。
   “已上传”只表示已上传中继，不表示对方已经接收。文件中继临时保存密文，过期或失败时可能需要重新发送。
   传输中可点击“取消传输”，无需联系人仍处于已核验或就绪状态；网络未就绪时也可请求本机取消。对方已保存的副本无法撤回。
9. 点击“锁定”会结束核心和 Tor。闲置 5 分钟、锁定 Windows、收到系统睡眠/唤醒通知、Tor 或核心管道意外中断也会触发锁定。
10. 切换联系人会清空草稿。复制/剪切设置剪贴板隐私标记，并尽力在 30 秒后或锁定时清除本应用复制的内容，无法控制所有第三方剪贴板软件。

文件隐私：传输使用原生核心的端到端加密并强制经过 Tor；新 XFTP 文件流需手动接收，缓存以密文保存，导出前校验完整性。每次发送自动使用“文档-随机编号.txt”，原文件名不发送，本机文件不重命名。发送确认框、文件消息和默认另存为名称均使用同一随机名称；再次发送会产生新名称。历史消息和已排队任务不改名。
纯文本处理不修改原文件，不复制原文件的附加数据流或文档元数据容器；不会生成明文临时文件。正文、Unicode 格式字符和换行会保留，里面的姓名、地址、链接也会保留。随机命名不会隐藏正文、文件大小和发送时间，也不是恶意内容扫描；接收方可以保留或转发。
本版不提供图片预览、语音播放或自动打开。上游核心的旧式内联语音可能按其自身规则写入加密缓存，因此不能把“手动接收”理解为覆盖所有上游附件类型。
解锁后点击顶部“附件缓存”，查看三个附件目录的已用空间、在途预留与可清理空间。新任务按 512 MB 预算检查；预留按未结束任务的完整大小保守估算，可能高于最终占用，重启后仍有效。这不是系统磁盘硬配额，旧任务和底层其他附件类型不会被强制停止。选择“清理并锁定”会断开连接并清理已结束附件的本机副本，完成后需重新解锁。聊天文字、进行中的任务、原稿和已经另存为的文件保留；被清理的附件无法再从本机另存为，请提前保存。删除文件不等于取证级安全擦除。请勿删除整个资料库。

资料位置：%LOCALAPPDATA%\PrivateChatDesktop。数据库和缓存由核心加密；口令不要写在此目录。没有口令找回服务。

升级前请在旧版结束或取消正在进行的非文本附件传输。新规则约束本版新选的文件与导出，不会清空核心中原来已排队的任务。更新前退出应用。更新、卸载保留资料库。最低 Windows 10 2004，推荐已安装安全更新的 Windows 11 x64。

未读提示：联系人旁显示未读数量，超过 99 条显示 99+。数量保存在加密资料库内；只有前台、无遮挡会话里实际显示的消息标为已读，不会开启对外已读回执。后台或历史页以外的消息仍保留未读状态。锁定后隐藏这些信息。
文字重试：明确发送失败的文字消息下方可点“重试发送”。程序会重新检查消息状态和安全码，再发送一条新消息；原消息保留，重复点击不会反复提交。等待发送、发送警告或结果未知的消息不会自动重发。出现结果未知提示时，先查看最新记录或向对方确认，再点“已核对记录”；该按钮只解除发送限制，不会发送内容。不能保证端到端绝无重复送达。TXT 附件失败仍需重新选择文件发送。
连接修复：聊天顶部点击“连接修复”查看状态。网络不通先“重连 Tor”；只有核心报告允许或需要修复时，才可点击“修复加密连接”。让双方保持在线，完成后重新核对安全码；不会删除联系人、记录或改成直连。

数据销毁（0.10.7）：点击顶部“数据销毁”，输入当前资料库口令，再点“检查本机资料”。应用先停止聊天与 Tor，离线验证口令并列出删除清单。检查阶段不会删除文件。确认范围后勾选提示，输入“销毁账号与聊天数据”，再点同名按钮，一次删除本机身份、联系人、所有聊天、附件缓存、Tor 缓存及内部恢复旧副本/备份临时副本。不放入回收站，无法撤销。
销毁身份不包含另存的旧 .pcbackup 备份和导出的 TXT；保留备份和对应口令仍可能通过兼容旧版恢复旧身份与记录，TXT 仍可独立读取。资料目录中无法识别的条目会保留并提示。本版已移除备份删除入口。
若删除中途停止或失败，部分文件可能已经清除。密钥阶段会先尝试全部已确认的密钥，之后才响应停止；一项失败不会阻止尝试其他已确认的条目。只要有失败，程序将阻止打开或恢复尚未清理完的身份；重新进入“数据销毁”，检查剩余清单后再次确认。不要手动移除 .delete-pending 标记来绕过保护。成功清除身份后应用自动退出，再次打开可创建新的本机身份。
界面显示核验进度。文件被占用或含附加数据流、稀疏/压缩/EFS 属性等无法可靠核验的情况会报告未完成；不会绕过检查强行报成功。本功能包括应用级密钥清除和文件完整覆写核验，不是经过认证的 SSD 安全擦除。不能保证取证无法恢复，也不能删除对方记录、文件系统日志、系统快照、同步软件或云端副本。没有修改系统恢复设置或擦除整盘。

支持：一对一文字、加密 TXT 附件、邀请、安全码核验、历史翻页、自定义 SMP 消息中继、未读提示、文字重试、连接修复、本机身份销毁与本地加密升级。
不提供：备份创建、恢复和删除。暂不支持：群聊、通话、扫码、多设备同步、自动可信更新、联系人屏蔽。
历史每页最多 100 条；查看旧消息时新消息不会切换当前页。
自定义中继：解锁后打开“消息中继设置”，每行一个完整 smp:// 地址，最多 8 个。测试全部通过后启用；编辑后需重测。设置保存在加密资料库中。已有联系人不会自动迁移，发送仍可能经过对方选择的中继。文件继续使用核心配置的 XFTP 中继。

这是未经独立安全审计、没有发布者代码签名的测试版。已有用户反馈文字聊天在不同网络下基础测试成功；新文件功能的真实跨电脑验收仍待完成。自动测试范围见 TESTING.md，不代表对所有终端攻击、磁盘取证或流量关联攻击安全。
窗口请求 Windows 屏幕捕获排除，不能防相机或恶意软件；网络检查不等同于完整 DNS/UDP/TCP 抓包。
请先使用虚构文件。不要关闭 Windows 安全防护；下载来源和散列校验不能替代可信签名。

Windows 网络隔离：本版核心不具有直接外网访问权限，Tor 与网桥进程保留必要联网权限。首次启动会为本应用创建 Windows 隔离身份，无需管理员权限。请保持 Windows 防火墙开启；隔离或系统策略检查失败时停止启动，不回退为普通进程。系统边界覆盖聊天核心，隔离环境内的具体 Tor 路径仍由应用强制代理配置控制。
